# usb_midi — ESPHome external component

Class-compliant USB-MIDI 1.0 device for the ESP32-S3, built on
[TinyUSB](https://github.com/hathach/tinyusb) via Espressif's
`esp_tinyusb` IDF managed component.

Plug the deck into a host (macOS / Windows / Linux / iPadOS) and it
enumerates as **"CDJ-1000MK2 controller"** with no driver install.
Traktor (or any DAW) sees it as a standard MIDI input.

## What it exposes to YAML

| Method | Args | Notes |
|---|---|---|
| `send_note_on(ch, note, vel)` | 0–15, 0–127, 0–127 | |
| `send_note_off(ch, note)` | 0–15, 0–127 | |
| `send_note(ch, note, vel)` | as above | velocity 0 → note off |
| `send_cc(ch, cc, val)` | 0–15, 0–127, 0–127 | |
| `send_pitchbend(ch, val)` | 0–15, −8192…+8191 | 14-bit signed; re-biased to centre 0x2000 internally |
| `is_mounted()` | — | true once USB enumeration finished |

Call any of these from a YAML lambda once you have the `id:` of the
`usb_midi:` block:

```yaml
usb_midi:
  id: usb_midi_dev
  manufacturer: "cdj1000 project"
  product: "CDJ-1000MK2 controller"
  serial: "CDJ1000MK2-0001"

binary_sensor:
  - platform: gpio
    pin: GPIO15
    name: "CUE"
    on_press:
      - lambda: 'id(usb_midi_dev).send_note_on(0, 61, 127);'
```

## What it doesn't do (yet)

- **Receiving MIDI from the host** — TinyUSB exposes incoming bytes via
  `tud_midi_available()` / `tud_midi_stream_read()`, but we don't drain
  them yet. Once the v0.2 display-feedback work needs it, drop a small
  poll in `loop()`.
- **SysEx / running status / 14-bit CC pairs** — sender is byte-perfect
  per the 3-byte channel-voice messages we need today. 14-bit CC for
  pitch is handled at the YAML layer using two CCs; SysEx is unused.
- **Multiple virtual cables** — single cable (cable 0). Hosts treat it
  as "Port 1". If we ever want a second cable for jog-wheel feedback,
  bump `CFG_TUD_MIDI` config and add the second `TUD_MIDI_DESCRIPTOR`.

## Build / wire-up notes

- IDF dependency is added automatically via `add_idf_component` in
  `__init__.py` — no manual `idf_component.yml` editing needed.
- `tusb_config.h` enables the MIDI class and disables everything else.
- Descriptors are generated by TinyUSB's `TUD_CONFIG_DESCRIPTOR` and
  `TUD_MIDI_DESCRIPTOR` macros in `usb_descriptors.c`, so we don't
  hand-write the audio-class hierarchy.
- VID `0x303A` is Espressif's allocated USB-IF range. PID defaults to
  `0x4D49` ('MI'); override in YAML if you need it unique against other
  ESPHome devices on your bench.

## Wiring sanity

The S3 DevKitC-1's USB-C jack is the device port. Plug it straight into
the host. No external USB-PHY needed (the S3 has one onboard).

For multiplexing power separately from data (e.g. powering the deck from
a dedicated USB charger while data flows to the laptop): use a USB-C
"data-only" cable on the host side and a power-only cable on a separate
USB-C jack via a power injector. The DevKit's single USB-C carries both
by default and is fine for v0.1.
